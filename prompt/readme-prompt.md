STYLE RULES
- Write for someone who has never seen the project. Lead with outcomes, not technology.
- Short sentences. No buzzwords, no "revolutionary", "seamless", "cutting-edge", "powerful".
- Every claim must be true and checkable. If something is untested, say so in Known limits.
- Use emojis only in section headings and the benefits table, one per item.
- Use tables for anything with two or more attributes; use numbered lists only for steps.
- Put all commands in fenced code blocks with a language tag.
- Technical detail goes in the lower half; the top half must be readable by a non-developer.
- No local file paths, usernames, or personal details from the development machine.
- Do not mention any AI assistant or tool used to write the code or the README, and add no
  "generated by" or co-author lines.
